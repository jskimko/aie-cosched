\subsection{Overview}
\label{subsec:overview}

% VALUE: the scheme in the core rule's order (read, rewrite behind checkers, price), each component after the property that requires it: the order is fixed in the artifact, so it is read there; each false dependence bounded before any rewrite is built; OPCORD did not compile the design, so its checkers refuse what the artifact and the host's accesses do not show legal; a reorder and a rename remove Section 3's waits; what pays changes with the prompt, so probes and an event model price each candidate per prompt length; a runtime runs the choice
Figure~\ref{fig:framework} shows OPCORD's components, which take a design that its stack has already compiled.
Because the CP's instruction order is fixed in the design's artifacts, OPCORD's analysis reads that order as a dependence graph over every agent that touches state, from open and closed binaries alike (Section~\ref{sec:order}), and bounds what removing each false dependence could recover before any rewrite is built (Section~\ref{subsec:removal}).
Since OPCORD rewrites designs it did not compile, its checkers refuse any rewrite they cannot show legal (Section~\ref{subsec:legality}).
To remove the waits of Section~\ref{subsec:losses}, our composer and stream pass reorder issue, and our loop pass renames decode attention's buffers (Section~\ref{subsec:order}).
What pays changes with the prompt, so an event model prices every candidate per prompt length from \emph{probes}, which time each operator dispatched alone (Section~\ref{subsec:pricing}), and a runtime runs the choice (Section~\ref{subsec:impl}).

% VALUE: general benefit, by what each component needs from a stack: reading, bounding, legality and the stream pass work on any stack's streams, compiled or lifted; the loop forms and the loop pass need the lowered design; the composer, probes, event model, choice and runtime are built for attention/GEMM fused prefill, and the composer and runtime need an open host program; choosing the configuration needs the stack's own build of each split
The analysis, the bound, the legality conditions, and the stream pass with its checker work on any stack's instruction streams, compiled or recorded, so a team with a closed stack's source can run them on its own designs.
Their loop forms and the loop pass need the lowered design.
The composer, the probes, the event model, and the runtime are built for a fused prefill that pairs attention with GEMMs, the composer and the runtime also need an open host program, and the choice of configuration ranges only over the splits that the design's stack builds.

\subsection{Reading Compiled Designs}
\label{sec:order}
\label{subsec:reading}
\label{subsec:model}

% VALUE: the analysis's terms: a phase as operations on agents (CP, DMA channels, core loops, host) with read and write sets over locations, every exclusively held resource a location, so run-time arbitration is a conflict on a location; the host as an agent; static control gives one fixed set of operations, data-dependent loops reported and left out; happens-before edges from mechanisms, not issue order; segments
% SOURCE: operations, locations, and static control (vault lab-cosched-passes (30), item 1); every loop analysed: on all nine fused decodes 0 loops refused (aie-cosched results/2026-10-23-phase-rerun, registered 7687182; mlir-aie dev line 0c5e8e37fac, 6b9e6666991, lit 46/46), and all 3,488 MLIR-AIR prefill loops judged (decisions log, loop census part 3; mlir-aie ba266793aa8); the host's static control (outline v9 section 1); the decode kernels' early return on the pad block branches on a runtime parameter, so it stays static per context length (lab-decode-long-context (10)).
% SOURCE: the mechanism table, attribution order, granularities, UNATTRIBUTED, and issue edges (vault lab-cosched-passes (30), item 2); the library AIECoschedDeps (mlir-aie f1725dae1f1, pinned); segments as in txn.segments (amd-npu a0ee2ed prefill-overlap/txn.py); one edge per (wait, gated op) pair (lab-cosched-passes (30), item 3).
The analysis represents a \emph{phase}, meaning all the dispatches that the host issues for a prefill or a decode step, as operations on \emph{agents}: the CP, the DMA channels, the cores' loops, and the host, whose steps between dispatches access the buffers that those dispatches bind.
Each operation reads and writes \emph{locations}, where a location is any resource that one operation holds exclusively, from memory bytes and BDs to locks, DMA channels, task-queue slots, and switch ports, so run-time arbitration on a shared port or lock is a conflict on a location.
Under the designs' static control, a phase has one fixed set of operations, and a loop with data-dependent control is reported and left out.
A \emph{happens-before} edge from $a$ to $b$ says that $b$ starts only after $a$ completes, and edges come from mechanisms such as synchronizations, BD chains, and locks, not from issue order.
Within one operator's stream, a \emph{segment} is a run of synchronizations followed by the issues they gate.
% VALUE: the validity assumption the legality rests on: a core touches a shared buffer only between the locks that guard it (Eraser's lockset discipline, cited; MLIR-AIE's object FIFOs guarantee it); it suffices because every synchronization appears in the streams read; on closed designs it cannot be checked, so verdicts there rest on it
% SOURCE: spine v18, "The system", the principle and the validity assumption (vault paper-cosched-spine-v18).
The analysis assumes the lock discipline that Eraser checks~\citep{savage1997eraser}, namely that a core touches a buffer it shares only between the locks that guard it, and MLIR-AIE's object FIFOs guarantee it by lowering their acquires and releases to those locks.
The assumption suffices because every synchronization appears in the streams we read.
On a closed design, whose core programs we cannot read, our verdicts rest on it.

\label{subsec:closed}
% VALUE: lifting: every stream read, compiled or recorded, round-trips byte for byte through MLIR-AIE's runtime sequence; on a closed stack: record at the runtime boundary, attribute each issue to a column group by decoded routes, observe the host there; bound only rewrites that leave the closed host program as it is, and replay only to test a bound, never to deploy
% SOURCE: recording libhrx (FastFlowLM 44d01787, gemma4e-flash), every prompt length 1-1,024 recorded with 0 /dev/accel opens; 8 buckets, 218 distinct streams, round trip and identity 218 / 218 (vault lab-cosched-passes (14)); lifter fix mlir-aie 91f64387ffb, 375 / 375 MLIR-AIR streams byte-identical (lab-cosched-passes (3)).
% SOURCE: streams recorded with a library that never opens the device, or captured with an XRT interposer during a device run (gemma4e-flash:e2b, 1,009 tokens; appendix-body.tex, app:capture (cut 2026-10-24)); route maps from the cdo_routes decoder: shim 3 and shim 6 MM2S0 reach only columns 0 and 7 (vault lab-flm-streams (11), (13)).
% SOURCE: the closed-stack rule and the host observed at the driver boundary (spine v18, The system; census partb/README); the measured rewrites are the merges at the 128-token bucket and e4898ce3's stream (census partb/replay/, registered 3ae0370, 67d54fe).
Every stream the analysis reads, compiled or recorded, round-trips byte for byte through MLIR-AIE's runtime sequence (i.e., its intermediate form for a dispatch's stream).
A closed stack such as FLM ships its designs as binaries with the runtime that issues them, so we record their streams and the host's accesses at that runtime's boundary, lift the streams into the same form, and attribute each issue to a column group by the routes decoded from the design's configuration.
On a closed stack, OPCORD only bounds rewrites that leave the closed host program as it is, and it replays a few with room under their bound on the device, to check the bound against measurement (Section~\ref{subsec:census}) and never to deploy them.

% VALUE: the dependence classes: each edge labelled true, name, or order by the pairs it alone orders (true: a read after a write; name: a write after a read or write; order: otherwise), loop-carried edges over the loop's iterations; the same graph decides the condition's two clauses, which is not a separate step
% SOURCE: classification by Lost(e), REDUNDANT, CONTROL, loop-carried distance (vault lab-cosched-passes (30), item 3); computed at stream granularity by aie-cosched-stream-deps (mlir-aie 2392abdc230 onward, fixture stream-turns with ORDER, NAME, RAW and REDUNDANT edges, lab-cosched-passes (49)), which agrees with its Python oracle on every compared count on 792 of 793 population streams, the 793rd too large for either (mlir-aie 0489d325082, lab-cosched-passes (53)); at loop granularity by AIECoschedDeps, whose buffer classes are the Lost-pair classes of the loop-carried edges (lab-cosched-passes (33)), with order edges and critical cycles computed in results/2026-10-23-order-loop (mlir-aie dev 58569749d3e..36f725e8e6e).
% DECISION: the classes are computed by the analysis; the stream-granularity instances of Section 3 were identified by reading the designs and confirmed by measurement, so the text never says that the analysis found them.
The analysis labels each edge by the pairs of operations that the edge alone orders, and it labels a loop's carried edges over the loop's iterations.
An edge is a true dependence if, in one of these pairs, the later operation reads a location that the earlier one writes, otherwise a name dependence if, in one of them, either operation writes a location that the other reads or writes, and otherwise an order dependence.
The same graph decides both clauses of the condition of Section~\ref{subsec:question}, since its agents and locations show whether two operations share a core tile or a DMA channel, and its true edges, including those through the host's steps, show whether one consumes the other's results.

\subsection{Bounding a Removal}
\label{subsec:removal}

% VALUE: the bound per false dependence: T/(T - O(d)) over typed resources (column groups, the CP with its per-dispatch cost, the DRAM read rate up to its cap, DMA channels one group shares with another); T the longest path, or the maximum cycle mean in a loop (cited); O(d) zero off every longest path and critical cycle, so the critical-path test discards sets that leave one uncut (cited for paths); the condition in the bound (1.000x where no true dependence fails; what buffers on the shared route let through where only disjoint resources fails) with the channel's hand-over; Amdahl's law for an ordering (cited), durations from the probes on AIR and timed dispatches elsewhere
% SOURCE: the bound and its typed resources (outline v9 section 2, C1; vault lab-bound-validation (1)); the buffering on a shared channel: pass-0 aie-cosched de43b4d (model) and eb7b29b, 8d03ffe (the clause test's 1.084x; passes/results/2026-10-26-buffering/README.md).
% SOURCE: the test is the in-tree set test, acyclic half (longest path, cut, next longest; mlir-aie 7240529eb562, lit 19/19) and loop half (periodic graph, Howard's algorithm, critical subgraph; mlir-aie 54a8b8e192c, lit 10/10) (vault paper-cosched-decisions-log, P1 and P3).
By Amdahl's law~\citep{amdahl1967validity} applied to an ordering, removing a false dependence $d$ can speed a phase up by no more than $T / (T - O(d))$.
Here $T$ is the phase's time, and $O(d)$ is how long $d$ alone keeps work on disjoint resources from running at once.
The typed resources are the column groups, the CP with its per-dispatch cost, the DRAM read rate up to its cap, and each DMA channel that two groups share.
The time $T$ is the longest path through the graph once each typed resource adds the order in which it serves its work, and in a loop it is the maximum cycle mean~\citep{ghamarian2006throughput}.
So $O(d)$ is zero where $d$ lies off every longest path, or in a loop off every critical cycle, and we discard any set of removals that leaves one of them uncut, which for paths is the critical-path rule of interaction-cost analysis~\citep{fields2003interaction}.
Because true dependences stay edges and no rewrite can duplicate a core tile or a DMA channel, a false dependence that fails the no-true-dependence clause of the condition (Section~\ref{subsec:question}) frees no overlap and bounds at $1.000\times$, and one that fails only disjoint resources frees at most what the buffers on the shared route let through.
When two operations share a DMA channel, the channel passes to the next operation once the last of the first's data is held in its consumer's buffers or in the route's switches, so the consumer's work on that data can overlap the next transfer.
The durations come from the probes on AIR's designs and from timed dispatches elsewhere.

% VALUE: removals taken at once: false edges deleted together, in-dispatch rewrites and merges as shorter durations; with each shared resource kept in the program's order, T over that graph's longest path bounds the rewrites that keep those orders; over every order, legal or not, nothing beats the maximum of five times, and T over that maximum is the joint bound; the bound decides which rewrites to build but cannot predict a loss, which the event model prices
% SOURCE: true joint b = T0 / max(longest path over true and narrowed edges with no resource order, busiest resource's summed durations, host steps' total, (commands - merges) x F at F = 195 us, DDR bytes / 54.9 GB/s) (pass-0, aie-cosched census_partb_terms.py true_joint(), 4ccbbff, tested; P1 rows 9eb00c8, summary b1f1e25; overlap-only rows 152a144, summary 08e9a2a).
% SOURCE: the fixed-order joint (schedule() with the recorded order kept on shared resources, 55e5c6e) bounds only the rewrites that keep each shared resource's order (P/4-method.tex:102 SOURCE); FLM's merge bound of 1.075-1.093x is that form over the legal rewrite space (terms5, e8232aa), against the five-term form's 1.1297 at e4b-p128 warm, whose fixed-order joint is 1.0927 (P/7-eval.tex:249 SOURCE).
% SOURCE: the composed order against the original at two chunks (256 tokens), S2, measured 0.922-0.980 on all five LLMs (figs/data/accuracy-cells.json, development cells); every 256-token pick is the original order (figs/data/choice-final-form.json).
To bound removals taken at once, we delete their false edges together and enter rewrites inside dispatches and merges of dispatches as shorter durations.
With each shared resource still serving its work in the program's order, $T$ over that graph's longest path bounds the rewrites that keep those orders.
Over every order of the remaining dispatches, legal or not, no schedule finishes sooner than the largest of five times, namely the longest path over the true dependences with each wait narrowed to the data it needs and the host's steps in sequence, the work on the busiest resource, the host steps' total, the CP's costs at the remaining dispatches, and the DRAM traffic at the read cap.
The joint bound divides $T$ by the largest of these times.
The bound decides which rewrites are worth building, but it cannot predict a loss such as the host post-processing that reordering exposes at two chunks, which the event model prices (Section~\ref{subsec:pricing}).

\subsection{Legality and Checkers}
\label{subsec:legality}

% VALUE: legality from the artifact, since OPCORD did not compile the design, each rewrite judged as a whole; a reorder keeps every instruction once and each column's segments and each channel's pushes in order, and creates no hazard in three kinds: data and BDs (a read above its guarding wait returns stale data; each BD written before its push and never rewritten under a queued transfer), the task queue (a push onto a full four-deep queue is dropped and any wait on it never returns), and device state (neither instruction of an inverted pair writes the locks, parameters, or configuration of the other's group, or host bytes the other uses)
% SOURCE: the stream checker on every inverted pair: ranges (RANGE-OVERLAP), BDs (BD-REUSE, PUSH-BEFORE-BD-WRITE, QUEUE-OVERFLOW), order invariants (NOT-PERMUTATION, CHANNEL-ORDER, BD-ORDER, SKELETON-MOVED), routes (ROUTE-1-PORT, ROUTE-SHIM-LOCK), and fences of the same group (FENCE-CROSSED for lock, switch, core, and LOADPDI writes; FENCE-CROSSED-UNPROVEN for its runtime-parameter words) (legality.py's pairwise inversion rule, vault lab-cosched-passes (10), (14), (36); the C++ checker inside aie-cosched-schedule, P6 closed, lab-cosched-passes (57), cosched-flag b46744f63c6).
% SOURCE: the queue drops a push onto a full queue and sets the channel's sticky Task_Queue_Overflow bit; MLIR-AIE inserts a maskpoll on the channel's queue-size status before any push that could find the queue full (mlir-aie 661e5b6b171, #3734, include/aie/Dialect/AIE/IR/AIETargetModel.h, AIEXPasses.td insert-queue-polls options); FastFlowLM's recorded streams hold no such poll (npu-gap qstall scan of e4898ce3, 2026-10-25 night).
% DECISION: the conditions are stated as what the streams and their configuration can check, never as sufficient for every design.
% DECISION: the drop rule (QUEUE-DROP, DROP-UNDECIDED without a configuration) is in the checkers (landed at aie-cosched 0d74483 / mlir-aie 95be81b09e8; the CE5b-tightened checkers at b98abe9 / 19e156632e5, on which the final census ran, contain it), alongside QUEUE-OVERFLOW and the deadlock rule (QUEUE-DEADLOCK).
% VALUE: whole operators may interleave when neither can disturb the other's device state or buffers; a rename only for a location whose conflicts are all WAR or WAW, with a free slot (in a loop, one lock pair, one lock marking a slot free and one full, and room in BDs and local memory); the conditions are not claimed sufficient, and every rewrite run is also bit-identical
% SOURCE: the loop conditions: the class rule renames only buffers whose every cross-iteration conflict is WAR / WAW and leaves RAW-carried state untouched; one free / full lock pair, the BD and local-memory budgets (16 BDs, 64 KiB), checked on the input and re-derived on the output (lab-cosched-passes (33), (57)); the ring condition: no slot reused before its previous reader has completed (merged.colour and assert_no_hazard, amd-npu a0ee2ed).
% SOURCE: bit-identical logits for every composed prefill and append, and identical tokens and logits for every renamed decode (Section~\ref{subsec:setup} defaults; vault lab-decode-long-context (22)).
OPCORD decides legality from the streams, their configuration, and the host's accesses, and judges each rewrite as a whole.
A reorder keeps every instruction once, and each column's segments and each channel's pushes in their order, and it must create no hazard of any of three kinds.
On data and BDs, a read moved above the wait that guards the write it reads returns stale data, and a BD may not be written after its push or rewritten while a transfer that loaded it may still be queued.
On a task queue, a push onto a channel's full queue, which is four deep, is dropped, and any wait on it never returns.
On device state, neither instruction of an inverted pair may write the locks, runtime parameters, or configuration of the other's column group, or host bytes that the other uses.
Two whole operators on different groups may interleave when each writes only its own group's shim BDs, task queues, locks, and runtime parameters, they address disjoint host buffers or disjoint byte ranges of one, and neither writes a buffer that the other reads or writes.
A buffer may be renamed only where all its conflicts are writes after reads or writes, and in a loop only where one pair of locks guards it and its tile has room for a second slot in its BDs and local memory.
These conditions hold only where an operation's locations cover all the state it touches, so we do not claim that they suffice for every design; every rewrite we run also leaves the outputs bit-identical (Section~\ref{subsec:setup}).

\label{subsec:checkers}
% VALUE: the checkers: the composer and both passes each carry one; a failed check leaves the composition or stream unchanged and names its reason, and nothing is dropped to pass; the stream pass's checker tests every inverted pair and says whether a rewrite is shown illegal or only not shown legal; the composer's checker stops the composition; the loop pass refuses a buffer it cannot show renamable and re-checks its output; as passes, the checkers judge designs nobody has read
% SOURCE: stream checker in C++ inside aie-cosched-schedule, route facts from the device IR (mlir-aie cosched-flag e20940fac7e); any finding refuses the whole rewrite and the IR is unchanged; outcomes DECIDED (shown illegal) against RESOURCE-UNPROVEN, RANGE-UNKNOWN, TOOL-FAILED, PASS-ERROR (not shown legal) (vault lab-cosched-passes (57) steps 3-5, and the checker's reason list).
% SOURCE: composer checks (whole-operator condition, no early ring-slot reuse, each split within a shim BD's fields): own-group register writes (shim BDs and DMA queues, own cores' locks, own cores' runtime parameters), disjoint argument slots or byte ranges, segment order and every op once, assert_no_hazard on ring slots, BD iteration wrap 6 bits and stride 20 bits per GEMM, check_posted for commands in flight; each turns red on a defeated input (lab-prefill-overlap (3), (4), (9); lab-split-sweep (5), (35)); checks fail rather than drop, 26 / 26 (decisions log D24 N1).
% SOURCE: loop pass input checks (one free / full lock pair, free lock starting at 1, BD and L1 budgets, every BD block ending in a next_bd, use inside a block loop, supported loop control) and output check (ring as made, carried state's users unchanged, budgets), mlir-aie aie-cosched-pass-0 e9fc225b2b6 / ba7ea1aa552, cherry-picked to cosched-flag (lab-cosched-passes (56), (57) step 2).
The composer and both passes each carry a checker for these conditions, and a failed check leaves the composition, stream, or loop unchanged and names its reason.
No rewrite drops an operator or an instruction to pass a check.
The stream pass's checker tests every pair of instructions that a proposed order inverts, and it reports a refusal as shown illegal, where a condition is violated, or only not shown legal, where the stream cannot decide one, such as a buffer range that the stream does not fix.
The composer checks the whole-operator condition on every dispatch it forms, and the loop pass refuses any buffer that it cannot show renamable and re-checks, on its output, each renamed buffer's slots and the state that the loop carries across iterations.
Unlike a hand edit, which covers only the streams someone has read, the composer and the passes apply their checkers to every design they rewrite, including designs nobody has read.

\subsection{Reordering and Renaming}
\label{subsec:order}
\label{subsec:compose}

% VALUE: the composer, cause then response: queued dispatches run one at a time, so reordering them alone recovers nothing; the composer re-cuts the one-operator dispatches by list-scheduling the operators chunk by chunk, in the order the operators and the host's steps produce and consume data, into shared dispatches (the composed order); each dispatch takes the ready attention operator of the lowest layer and chunk, ready meaning the host has post-processed every output it reads, and adds ready GEMMs in the same order until their probe-estimated work reaches attention's, because a dispatch runs both groups in about the longer one's time; without a ready attention operator, the packing of the host policy bounds the GEMMs; concatenated segments, so composing never changes the work
% SOURCE: merged.plan (amd-npu a0ee2ed prefill-overlap/merged.py, now opcord/compose/merged.py at aie-cosched opcord-runtime 446fa1c): qkv(L, c) after down(L-1, c); attn(L, c) after qkv(L, 0..c); o after attn; gate and up after o; down after gate and up; GEMMs added in the same order until their estimated work reaches the attention operator's; an optional cap on the GEMMs per attention command.
% SOURCE: opcord/compose/merged.py at npu-gap-0/opcord-pin 836f84b: :13 "each command takes the ready attention op with the lowest (layer, chunk) plus ready GEMMs until their estimated work reaches the attention's"; :447 an op "is ready once every one of them has been posted (its host post-op run)"; :340-342 the GEMM estimates are "the shipped stage probe less the frozen F", attention's "the per-chunk probes"; a command without a lead takes up to batch ready ops.
% SOURCE: txn.segments and txn.compose (a0ee2ed prefill-overlap/txn.py, now opcord/compose/txn.py); compose asserts each stream's segment order, every op kept once, and equal headers.
Because queued dispatches run one at a time (Section~\ref{subsec:semantics}), reordering the original program's one-operator dispatches alone recovers nothing, so our \emph{composer} re-cuts them into shared dispatches, whose order we call the \emph{composed order}.
It schedules the operators chunk by chunk as the host's steps make their inputs ready: each dispatch takes the ready attention operator of the lowest layer and chunk, then joins ready GEMMs to it in schedule order until their work, estimated from the probes, reaches attention's, since a dispatch that runs both groups takes about the longer group's time.
Where no attention operator is ready, a packing limit bounds the GEMMs per dispatch, and this limit with the number of dispatches in flight forms the \emph{host policy}.
Since a composed dispatch concatenates its operators' segments, composing changes when work is issued and awaited but never what the work is.

% VALUE: the composer within a dispatch: every group's work opens before the CP waits on any, attention's two columns counted as two groups, synchronizations in the order the probes predict their transfers complete; attention issued once ready or held, so that it runs beside the GEMMs the previous one's consumers release, holding a candidate of the choice; opening every group first is the breadth-first issue order with which GPU streams' kernels ran at once on one hardware queue (cited), written here into one in-order stream behind a checker
% SOURCE: merged.cp_order (a0ee2ed, now opcord/compose/merged.py): the opening segments of both attention columns and of the first GEMM, then synchronizations by predicted completion; the in-turn order takes 1.26x as long on the same 38 commands (lab-prefill-overlap (16)).
% SOURCE: the hold is plan_graph's pipe depth, in the planner's default search at opcord-pipe 4a60cc4 (POLICIES carries pipe in {0, 1}; pipe 2 never priced better). Gate (npu-gap amd-npu 5fb90770, ab/results/pipe-2026-10-26): all 96 picks (60 paper, 36 D2) equal to b8fe009's; 40 of 276 per-split composed-order plans differ (N 129 and 256, pipe 1, predicted 0.1-8.2 ms cheaper, in cells whose pick is the original order); on the IRON layer the pick is the hold (6ac89c53).
% SOURCE: the hold's reason, opcord/compose/merged.py:497-499 (npu-gap-0/opcord-pin 836f84b): "The next chunk's lead then waits for the previous one's consumers and rides with the work they release ... instead of being spent before that work exists."
Within each dispatch, the composer opens every group's work before the CP waits on any, counting attention's two columns as two groups (Figure~\ref{fig:rewrites}a), and orders the synchronizations by the completion order that the probes predict, so that, where the predictions hold, each gated issue waits on its own transfer.
Opening every group's work first is the breadth-first order with which kernels of different GPU streams ran at once when the streams shared one hardware queue~\citep{rennich2012streams}, and the composer writes it into one in-order instruction stream behind its checker.
Each attention operator is either issued once it is ready or held until the GEMMs that the previous one feeds have finished, so that it runs beside the work those release; holding is a candidate of the choice (Section~\ref{subsec:pricing}).

% VALUE: the stream pass: the same reorder inside one operator's stream, compiled or lifted (each column's segments by position, columns interleaved position by position), so the CP issues each column's next work before it waits on another; it emits the hand alternation of Section 3 byte for byte; its proposals are what its checker judges
% SOURCE: aie-cosched-schedule (mlir-aie 573e0140174, identical in f1725dae1f1; in place on cosched-flag), proposal format /2 at aie-cosched 8dee63f; 42 / 42 decoded order and bytes equal to the hand versions (vault lab-cosched-passes (35), (40)); in place and byte-identical to the Python-applied moves and to the hand template on 42 / 42 (decisions log D24, P4).
% DECISION: the pass emits the alternation and the checker accepts it; it is never said to discover it.
Our \emph{stream pass}, which is an MLIR-AIE pass, applies the same reorder within one operator's stream, compiled or lifted (Figure~\ref{fig:rewrites}b): it interleaves the columns' segments position by position, so the CP issues each column's next work before it waits on another.
It emits the hand alternation of Section~\ref{subsec:losses} byte for byte, and its proposals are what its checker judges.

\label{subsec:rings}

Decode attention keeps its keys, values, and scores in one buffer each, so each block's transfer waits for the previous block's compute, which is a name dependence (Figure~\ref{fig:rewrites}c).
Our \emph{loop pass} renames these buffers into two-slot \emph{rings}, so transfer and compute pipeline.
It leaves in place the running maximum and the accumulator, which alone carry data from block to block, whereas AIR's double buffering declines the whole loop because of that carried state.

\subsection{Pricing and Choosing}
\label{subsec:pricing}
\label{subsec:split}
\label{subsec:formulation}

% VALUE: why OPCORD prices rather than runs (the artifact fixes the order but not the durations, and the candidates grow with chunks, configurations and removals), and the probes: each operator alone per supported configuration, attention chunks at several cached-context lengths
The artifact fixes the order but not the durations, and the candidates multiply with the chunks, the configurations, and the removals, so OPCORD prices each candidate without running it.
The prices come from probes taken on each supported configuration, with each attention chunk probed at several cached-context lengths.

% VALUE: the event model: an analytical simulation of the in-order dispatch queue (Eq. 1), two groups overlapping inside a dispatch (Eq. 2), every symbol defined, device times beyond the dispatch floor; the host timeline with its issue and post-processing costs and each program's waits
% SOURCE: opcord/model/event_model.py (opcord-runtime 3bead38): Eq. 1 at EM:122 (end = max(end_prev + eps, h + F) + busy, h the host clock after the issue cost, busy with the floor removed, the first command's eps 0); eps by command kind EM:114-121; GEMM-only commands, the stages' times plus gamma per extra GEMM, EM:406; the two-regime composition max(a, g) + a_r + b_r min(a, g), EM:13-18, 82-89; the composer's depth wait EM:170 and the shipped program's stage-major waits EM:179-224; the shipped program through the same simulate(), EM:402-403; refusal outside the measured contexts EM:239-240, a chunk at its absolute position EM:263-276; per-model post costs EM:346 and head EM:389 (npu-gap term checks, 2026-10-25).
% SOURCE: the floor in the work terms, pass-0 opcord/model/event_model.py at 3bead38, the module doc: "On work, a = A - F and g = G - F (each alone time pays one floor; the composed command pays one)".
% DECISION: this subsection states the frozen form (dev form, frozen 2026-10-25; amd-npu 12250226, FORM-A2.md; opcord-runtime 3bead38, opcord/model/event_model.py, constants opcord/model/constants/frozen.json), term by term as npu-gap checked it against the code.
The \emph{event model} is an analytical simulation of the device, the CP, and the host.
Because queued dispatches run one at a time, dispatch $k$ ends at
\begin{equation}
\label{eq:cmd}
e_k = \max\bigl(e_{k-1} + s_k,\; q_k + F\bigr) + \tau_k,
\end{equation}
where $q_k$ is when the host has queued the dispatch and paid its issue cost, $F$ is the dispatch floor, and $\tau_k$ is the dispatch's device time beyond that floor.
The transition $s_k$ from the previous dispatch is one constant per ordered pair of dispatch kinds, where a kind is attention or GEMM, and it is negative where the next dispatch starts before the previous one ends.
Without attention, a dispatch takes its GEMMs' times alone summed, plus a fixed $\gamma$ for each GEMM after the first, and with attention beside GEMMs it takes
\begin{equation}
\label{eq:overlap}
\tau_k = \max(a_k, g_k) + c_r + d_r \min(a_k, g_k),
\end{equation}
where $a_k$ and $g_k$ are the attention and GEMM groups' times alone, each beyond the floor, $r$ says which is longer, and $c_r$ and $d_r$ are a fixed cost and the fraction of the shorter time that the overlap leaves unhidden.
On the host's timeline, every dispatch pays an issue cost set by its kind, and every operator pays a post-processing step.
The host waits where each program does, stage by stage for the original program and, for the composer, on the oldest dispatch once its limit of dispatches is in flight.

% VALUE: what makes the price move with the prompt and keeps it honest: each attention chunk priced at its position, so the balance between the groups and the candidate that pays change with length; machine constants once from microbenchmarks (precedent cited), none fitted to an LLM's end-to-end runs
% SOURCE: frozen constants (opcord/model/constants/frozen.json; calibration hold 2026-10-22 22:20-22:43, amd-npu d94266bf, microbench device.json / host.json; frozen.json from npu-gap-0-c8 b15d9dca): F 94.507 us; transitions gemm->gemm 12.93, gemm->attn -6.65, attn->gemm 47.95, attn->attn 20.94 us; gamma 24.56 us; regimes GEMM-longer c 42.33 us, d 0.1160 (n 10), attention-longer c 21.43 us, d -0.0260 (n 5); issue attention 68.06, GEMM 7.36 us; post per model and operator (host.json, e.g. Llama-3.2-1B qkv 179.5, up 202.3, attention 76.1 us). The microbenchmarks run Llama-3.2-1B's layer-0 operators with real weights; tests/test_event_model.py forbids end-to-end sources in frozen.json.
Because each attention chunk is priced at its position in the prompt, the balance between the groups, and with it the candidate that minimizes TTFT, changes with the prompt length.
The machine constants do not depend on the LLM and come from microbenchmarks run once, as analytical models of communication and of memory-bound kernels measure theirs~\citep{culler1993logp,williams2009roofline}.
The host's post-processing costs are measured once per LLM, and no constant comes from an LLM's end-to-end runs, so Section~\ref{subsec:decision} tests the event model rather than calibrates it.

% VALUE: the choice per prompt length: price every candidate (each supported configuration; the original order with or without the stream pass; the composed order with attention issued once ready or held; each host policy) and run the minimum unless a short measurement settles a near tie; order and configuration chosen together because the configuration that minimizes each order's TTFT moves with the balance and differs between orders; the original order kept wherever composing is priced higher; the event model's choice scored without the near-tie measurement
% SOURCE: opcord/plan/planner.py choose(model, L, N): candidates every split with a committed probe (S1, S2, S4), orders ship / shipar / comp, composer policies depth {1, 2, 4, 8} x GEMM cap {none, 4} x packing {1, 4}, each priced by event_model.predict, the minimum returned with the whole table; the hold as pipe {0, 1} (opcord-pipe 4a60cc4).
% SOURCE: measure-when-close, implemented test-first in opcord (planner.CLOSE_BAND, close_candidates, decide; test_measure_close 10/10); bands same 5%, cross 15%, tie 0.5%, one warm and three kept runs per candidate (vault decisions log, "Spine v18 drafted; amendment-1 batch and measure-when-close approved").
Before a prompt length runs, OPCORD prices every candidate and runs the one with the minimum predicted time, except where a short measurement at planning time settles a near tie, and Section~\ref{subsec:decision} scores the choice without that measurement.
The candidates are each supported configuration, the original order with or without the stream pass, the composed order with each attention operator issued once ready or held, and each host policy.
Because the configuration that minimizes TTFT moves with the balance and need not be the same for both orders (Section~\ref{subsec:question}), OPCORD chooses the order and the configuration together.
Since the original order is itself a candidate, OPCORD keeps it wherever composing is priced higher.

\subsection{Runtime}
\label{subsec:impl}

% VALUE: the runtime: replaces the host program's dispatch loop, runs the choice and switches configurations; the rewrites touch only issue order, the cut into dispatches and buffer slots, so no kernel changes, and submitting to the design's own hardware context needs no driver or firmware change
OPCORD's runtime replaces the design's host dispatch loop, runs the chosen schedule, and switches configurations where the choice changes them.
Because the rewrites change only the issue order, the cut into dispatches, and the buffer slots, and the runtime submits to the design's own hardware context, OPCORD changes no kernel, driver, or firmware.
