On AMD Ryzen\texttrademark{} AI processors, the neural processing unit (NPU) runs each large language model (LLM) operator on its own group of AI Engine tiles, but one in-order command processor issues all of their work.
The compiled issue order is therefore the array's schedule, and in fused designs it makes operations wait on work whose results they do not use.
We present OPCORD, a post-compilation rescheduler that reads compiled NPU programs from any toolchain, closed binaries included, as dependence graphs, bounds what removing each such wait can recover, rewrites issue order and buffers under legality checkers, and chooses the order and array configuration per prompt length with an event model.

Pre-final: the decode development batch (step 2, section 5 item 3).
Across five LLMs, OPCORD reduces the time to first token (TTFT) by \PrefillGainLo--\PrefillGainHi$\times$ at 1K--32K tokens over each design's original program on its fastest measured configuration, and decode time per token by \DecodeGainLo--\DecodeGainHi$\times$ at about 30K tokens, with bit-identical outputs.

Designs from an open compiler that trail a closed production engine's current release at 16K tokens on four of five LLMs then reach the first token \AbsGainLo--\AbsGainHi$\times$ sooner than it on all five at 1K--16K tokens.
How much a rewrite recovers depends on how a design cuts its work and on the prompt length, as predicted by a condition read from the compiled program.
