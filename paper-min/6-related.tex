\textbf{Operator Scheduling and Concurrency.}
IOS and Nimble run independent operators concurrently on GPU streams~\citep{ding2021ios,kwon2020nimble}, and IOS fits a schedule to each batch size by measuring candidate stages on the device.
Rammer fixes a spatio-temporal schedule of a DNN's operators at compile time~\citep{ma2020rammer}, and other systems order or overlap operators within or across devices~\citep{barham2022pathways,pan2026dynaflow,jax-pgle,zhu2025nanoflow,gandhi2026dataflow} or across an SoC's processors~\citep{jun2026heteromosaic,wei2025agentxpu}.
LATTICE reorders NPU command graphs taken from traces~\citep{liu2026lattice}, taking the graph's dependences as given.
On mobile NPUs, llm.npu runs prefill as fixed-size chunks on pre-built graphs and, at run time, issues the chunks' subgraphs to the CPU/GPU and NPU out of chunk order, picking each from profiled times, with each processor running one subgraph at a time~\citep{xu2025llmnpu}.
Unlike these systems, which construct a schedule from a program or a traced graph, OPCORD starts from the one that the CP's order in compiled binaries already fixes, closed ones included, and derives there the dependences that keep operators on disjoint column groups of one array from running at once.
In open designs, it chooses that order with the configuration per prompt length, without running each candidate.

\textbf{GPUs and Statically Ordered Machines.}
On Fermi GPUs, one hardware work queue placed the order dependences of Section~\ref{sec:background} between streams, and kernels of different streams ran at once when issued breadth first~\citep{rennich2012streams}, as our composer issues them (Section~\ref{subsec:order}).
Kepler's Hyper-Q then added hardware queues that remove these false dependences among streams~\citep{nvidia-kepler-gk110}.
At the static end, Groq's TSP lets its compiler determine when every instruction executes~\citep{abts2020tsp}, and ReGate lets an NPU's compiler power-gate idle vector units and SRAM~\citep{xue2025regate}, saving energy during idle time rather than removing it.
XDNA~2 sits between the two ends, since its program fixes the order of each engine's work but not its duration, and because each hardware context has one in-order CP and a second context shares the whole array in time, the breadth-first order must be written into one instruction stream.

\textbf{NPU and AI Engine Compilers.}
AIR and IRON compile operators and fused multi-operator designs onto the AIE array~\citep{wang2026mlirair,hunhoff2025iron}, and Stream, compilation flows and programming models automate the mapping of layer-fused and dataflow designs~\citep{symons2025stream,zhuang2025aries,danopoulos2025aie4ml,chen2024allo,fang2025dato}.
On XDNA NPUs, a FlashAttention case study compares expert-chosen mappings, up to a fused AIR kernel~\citep{wang2026flashattention}.
AscendNPU-IR places a kernel's synchronizations as it lowers, so that the fewest hardware events are used~\citep{ascend-autosync}.
These tools generate a design from a program, whereas OPCORD takes designs as compiled, reading and bounding closed ones and, in open ones, removing the false dependences that the condition of Section~\ref{subsec:question} says can free overlap, rather than placing the fewest synchronizations.

\textbf{Binary Analysis and Rewriting.}
Analysis and rewriting after compilation are established for CPUs and GPUs, from parallelizing binaries without their source~\citep{kotha2010automatic} and laying out code from profiles~\citep{panchenko2019bolt} to reordering a compiled GPU kernel's instructions by a measured search~\citep{he2025cuasmrl} and recovering a closed driver's command streams to attribute runtime behavior~\citep{yan2026revealing}.
These analyze one processor's instruction stream or recover a closed driver's command stream, whereas OPCORD analyzes and rewrites the instruction streams that coordinate several kinds of engines, and decides legality from the access sets of every agent that touches state.

\textbf{Performance Analysis and Models.}
Daydream and dPRO predict what an optimization gains by simulating it over run-time traces~\citep{zhu2020daydream,hu2022dpro}.
GPA attributes GPU instruction stalls within a kernel and estimates each fix's speedup~\citep{zhou2021gpa}, and interaction-cost analysis costs a set of events together~\citep{fields2003interaction}.
Learned, analytical and SDF models predict or bound time from a given tensor program, mapping or graph~\citep{kaufman2021learned,parashar2019timeloop,kwon2019maestro,ghamarian2006throughput}.
DietCode generates tensor programs from which its runtime selects one per input shape, within each operator~\citep{zheng2022dietcode}.
In contrast, we bound each removal of a false dependence before it is built, from the program's order and measured durations alone, and price whole orders and configurations of a compiled design from each operator's time alone.
