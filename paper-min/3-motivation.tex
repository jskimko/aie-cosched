\subsection{Dispatch Semantics}
\label{subsec:semantics}

% VALUE: queued, or in sequence in one dispatch, two operators take the sum of their times less at most one floor, so packing dispatches does not free overlap; one dispatch that issues both groups' work before waiting on either runs the pair near the longer operator alone, its excess near the read cap; a second hardware context time-shares the same columns; so concurrency comes only from the order inside a dispatch
% DECISION: packing several operators per dispatch (batching) is cited as standard practice, never presented as ours.
% SOURCE: queued / in-sequence = 1.007-1.029 on 7 pairs, 20 runs per pair (amd-npu 17f7ec3 prefill-overlap/ovl4/, lab-prefill-overlap (5)b); in-sequence / (A + G - F) = 0.996-1.021 over 17 pair runs (ovl/, ovl2/ at 8f13e05 and ovl4/; report.txt H1 column).
% SOURCE: XRT run list, /opt/xilinx/xrt/include/xrt/experimental/xrt_kernel.h:21 (XRT 2.25.0).
We pair one attention operator of the original program with one GEMM on disjoint column groups.
Two dispatches queued on one hardware context run within 3\% of one dispatch that holds both streams in sequence on each of seven pairs, and that dispatch takes the sum of both operators' times less at most one dispatch floor (Figure~\ref{fig:rewrites}a, before).
Packing dispatches, as CUDA Graphs~\citep{nvidia-cudagraphs}, XRT's run lists~\citep{xrt-repo}, and an MLIR-AIR deployment of LLMs on this NPU~\citep{li2026agentnpu} do, therefore recovers none of the overlap.
% SOURCE: amd-npu d8c63fb1 roofline/two-ctx-hold/two_ctx.json: rho 1.970, 95% bootstrap CI [1.955, 1.976], same-context ratio 1.970; medians solo 19.76 / 19.81 ms, pair 39.10 ms, same 39.09 ms (vault lab-prefill-overlap (34)); driver allocation amdxdna 2.25.0 npu4_regs.c:94-106, aie2_ctx.c:604-608 (vault lab-prefill-overlap (31)); the design is a one-column xclbin (AIE_PARTITION column_width 1, amd-npu 2171857e roofline/two-ctx-build/; vault lab-prefill-overlap (33)).
A second hardware context recovers none either, because it shares the same eight columns in time.
A one-column design run on two contexts at once takes $1.97\times$ its time alone, as two runs on one context do.
% SOURCE: interleaved / max(A, G) = 0.998-1.058 over 10 pair runs = 9 pairs (c8 + lm measured twice, 1.054 and 1.058; the figure keeps each pair's first measurement); GEMM shapes up, LM head chunk, down; attention chunks 0, 4, 8, 12, 15 (lab-prefill-overlap (3)).
% SOURCE: DRAM rate during the interleaved command 52.2 GB/s against a same-batch 8x2 cap of 53.9-55.3 GB/s for c8 + lm, the costliest overlap (1.054-1.058) (lab-prefill-overlap (3)); the cap is the 8x2 bracket's read of 256 MiB (Section subsec:setup's SOURCE).
In contrast, one dispatch that issues all the GEMM's work, then attention's stream, and only then the GEMM's synchronizations runs the pair within 6\% of the longer operator's time alone on each of nine pairs (Figure~\ref{fig:rewrites}a, after).
The small excess appears where the pair's DRAM reads approach the \emph{read cap}, namely the highest rate at which the column groups together can read DRAM.
Concurrency thus comes only from one dispatch that issues several groups' work before waiting on any, which makes the order inside a dispatch a scheduling decision.

\subsection{The Overlap Condition}
\label{subsec:question}

% VALUE: the condition: removing a false dependence frees overlap, beyond what buffers on a shared route let through, only where the freed work uses core tiles and DMA channels the awaited work does not use (disjoint resources, which no rewrite can duplicate) and no true dependence, on the device or through a host step, separates the two; together the two clauses are the condition; it refines the classical critical-path rule for this NPU, since a removal on the critical path frees more than buffers on a shared route let through only where both clauses hold; both clauses are read from the artifacts and the host's accesses before any duration, whereas the critical-path rule needs durations, which then decide the rest
% DECISION: the critical-path rule is classical and cited in Background; the paper's claim is the condition's platform terms (resources no rewrite can duplicate, the host as an agent) and its dependence on the partition and the prompt length, never "false dependences cost time".
% SOURCE: the condition and its resource wording (vault paper-cosched-decisions-log, "The lead", "The legality control is a designed single-hazard rewrite; the condition's resource wording", 2026-10-24); the buffering carve-out (pass-0 aie-cosched de43b4d, model; 8d03ffe, passes/results/2026-10-26-buffering/README.md).
Removing a dependence frees overlap, beyond what buffers on a shared route let through, only where the freed work uses core tiles and DMA channels the awaited work does not use.
We call this clause \emph{disjoint resources}, because a rewrite can reorder issue or rename a buffer but cannot duplicate a core tile or a DMA channel.
The second clause, \emph{no true dependence}, requires that no true dependence separates the two, on the device or through a host step.
Together the two clauses form the \emph{condition}.
The condition refines the critical-path rule for this NPU, since removing a dependence on the critical path frees more than buffers on a shared route let through only where both clauses hold.
Both clauses are read from the artifacts and the host's accesses before any duration is measured, whereas the critical-path rule needs durations, which then decide the rest through OPCORD's bound and event model (Section~\ref{sec:method}).

% VALUE: the partition decides where the condition holds: consecutive operators of a modular design share core tiles and DMA channels and fail disjoint resources; attention run once over the whole prompt makes every turn with the GEMMs a true dependence; AIR's chunked one-operator dispatches meet both clauses, so regrouping them into shared dispatches recovers their overlap, and decode's single buffers leave name dependences that meet both clauses
How a design partitions its work therefore decides where the condition can hold.
Consecutive operators of a modular design share core tiles and DMA channels, so they fail disjoint resources.
A fused design that runs each layer's attention once over the whole prompt makes every turn between attention and the GEMMs a true dependence.
AIR's prefill instead keeps one configuration and partitions its work into one-operator dispatches over chunks.
An earlier chunk's attention and a later chunk's GEMMs then meet both clauses, so regrouping those dispatches into shared ones can recover their overlap.
AIR's decode keeps one buffer per loop role, which leaves name dependences that meet both clauses too (Table~\ref{tab:census}).

% VALUE: the prompt length decides what the freed overlap is worth: attention's work per chunk grows with position while the GEMMs' stays fixed, so the balance between the groups, and whether overlap outweighs the host post-processing a new order exposes, moves with length; columns given to attention are taken from the GEMMs, so the configuration that minimizes TTFT moves too and can differ between orders
The prompt length then decides what the freed overlap is worth.
Attention on a later chunk reads more of the context, whereas a GEMM's work per chunk is fixed, so the balance between the two groups moves with the length, and with it whether overlap outweighs the host post-processing a new order exposes.
% SOURCE: the four-column split's GEMMs are 27% (1B) and 35% (Qwen3-4B) slower than on six columns (vault lab-split-sweep (4)-(5)).
Columns given to attention are taken from the GEMMs, so the configuration that minimizes TTFT shifts as the prompt grows and can differ between orders (Section~\ref{subsec:shape-eval}).
