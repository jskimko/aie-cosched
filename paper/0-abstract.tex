On AMD Ryzen AI processors, the neural processing unit (NPU) runs a large language model (LLM) on a spatial array of AI Engine tiles, where each operator executes as a dataflow on its own group of tiles.
A single command processor issues all of the array's work strictly in the order that the compiled program lists it, so that order is the array's schedule.
Designs that keep several operators resident on the array avoid reconfiguring it between them, but their compiled order and buffers often make work wait on other work whose results it does not use, and such false dependences can leave tiles idle.
Because the order and the buffers are fixed in the compiled program, these false dependences can be read, bounded, and removed after compilation.
We show that removing a false dependence frees overlap only where the freed work neither depends on the awaited work nor needs the compute tiles and data channels that it occupies, and that the design's partitioning and the prompt length set how much work qualifies.
We present OPCORD, which reads compiled NPU programs, open or closed, as dependence graphs and bounds what each false dependence costs.
It reorders instructions and renames buffers under checkers that reject any rewrite they cannot prove legal, and it chooses the order and the configuration for each prompt length with an event model of the device and its host.
Across five LLMs, OPCORD shortens the time to first token (TTFT) by \E{X--Y}$\times$ at 1K- to 32K-token prompts against each design's original program on the configuration that minimizes its TTFT.
It shortens decoding by \E{X--Y}$\times$ at 16K-token contexts and by up to \E{Z}$\times$ at 30K, and both keep the outputs unchanged.
On open-source designs, it also reaches the first token sooner than the current release of a closed production engine on every LLM and prompt length we compare, and our analysis explains why that engine's designs leave almost no overlap to recover.
