On AMD Ryzen\texttrademark{} AI processors, the neural processing unit (NPU) runs a large language model (LLM) on a spatial array of AI Engine tiles, where each operator executes as a dataflow on its own group of tiles.
Designs that keep several operators resident on the array avoid reconfiguring it, but their compiled order and buffers often make an operation wait for another whose results it does not use, and such false dependences can leave tiles idle.
A single command processor issues all of the array's work strictly in the order that the compiled program lists it, so that order is the array's schedule.
Because that order and the buffers are both fixed in the compiled program, false dependences can be read, bounded, and removed from it after compilation.
We show that the usual remedies of packing more operators into each dispatch and adding a second hardware context recover none of the lost overlap.
How much a rewrite can recover is set by the design's partitioning and the prompt length, and where it can recover nothing shows in the compiled design and its host program before anything is timed.
We present OPCORD, which reads compiled NPU programs, open or closed, as dependence graphs and bounds what each false dependence costs.
It reorders instructions and renames buffers under checkers that reject any rewrite they cannot prove legal, and it chooses the order and the configuration for each prompt length with an event model of the device and its host.
Across five LLMs, OPCORD shortens the time to first token (TTFT) by \E{X--Y}$\times$ at 1K- to 32K-token prompts against each design's original program on the configuration that minimizes its TTFT.
It shortens decoding by \E{X--Y}$\times$ at contexts of about 30K tokens, and both keep the outputs unchanged.
On open-source designs, it also reaches the first token sooner than the current release of a closed production engine on every LLM and prompt length we compare, and our analysis explains why that engine's designs leave almost no overlap to recover.
