On AMD Ryzen\texttrademark{} AI processors, the neural processing unit (NPU) executes large language model (LLM) inference on a spatial array of AI Engine tiles, mapping each operator to a dataflow on a dedicated group of tiles.
Fused designs, which keep multiple operators resident on the array, avoid reconfiguration, but their compiled instruction order and buffer allocation often introduce false dependences that can leave tiles idle, where an operation waits for another whose results it does not consume.
We identify that, because a single in-order command processor issues all of the array's work, the array's schedule is fixed in the compiled program rather than determined at run time, so false dependences can be located, bounded, and removed from the program after compilation.
The recoverable time depends on the design's partitioning and the prompt length, both of which can be analyzed from the compiled design prior to any measurement.
We present OPCORD, a system that analyzes compiled NPU programs, including closed-source binaries, as dependence graphs and bounds the cost of each false dependence.
OPCORD reorders instructions and renames buffers under checkers that reject any rewrite they cannot prove legal, and it selects the instruction order and array configuration for each prompt length using an event model of the device and host.
Across five LLMs, OPCORD reduces the time to first token (TTFT) by \PrefillGainLo--\PrefillGainHi$\times$ for prompts of 1K to 32K tokens, relative to each design's original program on its fastest measured configuration.
It reduces the decode time per token by \DecodeGainLo--\DecodeGainHi$\times$ at contexts of approximately 30K tokens, with bit-identical outputs in both phases.
Applied to open-source designs, OPCORD also achieves a lower TTFT than the current release of a closed production engine for every LLM and prompt length in the comparison, and our analysis explains why that engine's own designs offer little recoverable overlap.
