On a client NPU, a language model runs as per-operator designs on a spatial array of AI Engine columns whose work one in-order command processor issues.
Composing those designs into one command stream introduces false dependences, where work waits on other work whose results it does not consume, so disjoint column groups take turns while the device reads 92--97\% busy and no counter on it reports which columns are idle.
We take a design a stack has already compiled as the input to scheduling: we recover its ordering from the instruction streams the stack emits, re-emitting 625 recorded streams of three toolchains byte for byte to establish that the reading is faithful, attribute each wait to its textbook dependence class, and bound what removing a wait is worth from probes of each operator alone.
Three passes then remove these dependences, issuing every column group's work before the command processor waits on any group, renaming buffers into rings, and choosing the split of columns per regime; two of them are upstream in MLIR-AIE, so designs we never examined can take them.
Across five edge models, and against each shipped design at its own faster split with the optimization an expert would reach for first already applied by hand, the composed schedule shortens the time to the first new token by $1.14$--$1.49\times$, shortens decode at a 16{,}384-token context by $1.27\times$ and $1.16\times$ on the two models we decode, and shortens whole agent turns at that context by $1.15$--$1.32\times$, with bit-identical outputs; against a lower bound computed from the same probes it closes a median 65\% of the distance from that baseline to the bound, and between 34\% and 76\% across twelve configurations.
Concurrency on this array is free in the hardware and rationed by one in-order queue, which makes the order of that queue's commands the array's schedule.
