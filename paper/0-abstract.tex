On a client NPU, a language model runs as per-operator designs on a spatial array of AI Engine columns whose work one in-order command processor issues.
Composing those designs into one command stream introduces false dependences, where work waits on other work whose results it does not consume, so disjoint column groups take turns while the device reads 92--97\% busy and the runtime reports nothing about which columns are idle.
We take a design a stack has already compiled as the input to scheduling: we recover its ordering from the instruction streams the stack emits, re-emitting 625 streams of three toolchains byte for byte so that the analysis starts from exactly the instructions each stack dispatches, attribute each wait to its textbook dependence class, and bound what removing a wait is worth from probes of each operator alone.
OPCORD then removes the dependences that lie on the critical path: it reorders issue so that every column group's work, and each column of an operator, is issued before the command processor waits on any of them, and it renames the buffers of decode attention's loop so that each block's transfer overlaps the previous block's compute; the reordering within an operator and the renaming are MLIR-AIE passes, which accept or refuse, with a reason, any design that compiler builds. Because the faster split of the array's columns flips between prompts computed from scratch and appends to a cached context, OPCORD also chooses the split per regime.
Across five edge models, and against each shipped design at its own faster split with the optimization an expert would reach for first already applied by hand, the composed schedule shortens the time to the first new token by $1.14$--$1.51\times$, shortens decode at a 16{,}384-token context by $1.27\times$ and $1.16\times$ on the two models our loop pass rewrites, and by $1.08\times$ on a third where the same renaming is applied by hand, and shortens whole agent turns at that context by $1.15$--$1.32\times$, with bit-identical outputs; against a lower bound computed from the same probes it closes a median 65\% of the distance from that baseline to the bound, and between 34\% and 76\% across twelve configurations.
Concurrency on this array is provided by the hardware and rationed by false dependences, at the one in-order queue that issues every column group's work and inside the loops of a single operator.
