On a client neural processing unit (NPU), a large language model (LLM) runs each operator as a flow on its own group of tiles of a spatial array.
One in-order command processor (CP) issues all of their work, so the order fixed in the compiled artifact is the array's schedule.
Fused designs, which keep several operators in one configuration to avoid reconfiguring the array, can inherit an order in which independent groups take turns, or a loop that keeps one buffer per role, so that each block's transfer waits on the previous block's compute.
That order is fixed when the design and its host program are written.
Removing such a false order frees overlap only where the work it frees runs on core tiles and DMA channels that the work it waited on does not use, which are resources a rewrite cannot duplicate, with no true dependence between.
We show that how a design cuts its work and the prompt length set how much work meets this condition, so the issue order that pays changes with the prompt length.
OPCORD reads compiled artifacts, closed ones included, and bounds the false orders in them, replaying a closed design only to check a bound against measurement.
It removes the false orders whose removal pays, choosing the prefill's order and column split per prompt length with an event model, under checkers that refuse any rewrite they cannot show legal.
On an AMD XDNA~2 NPU, against the existing program on the supported split that minimizes its time to first token, OPCORD shortens the time to first token across five LLMs by \E{X--Y}$\times$ at prompts of 1K to 32K tokens.
Its loop pass, which renames decode attention's buffers, shortens decode by \E{X--Y}$\times$ at 16K-token contexts against the unmodified decode design, and both keep the outputs bit-identical.
Across the designs we read from three stacks, every overlap gain we measure falls where the condition says one can arise.
The condition also explains why a closed production stack leaves almost no overlap to recover in either of its prefill engines: one runs each layer's attention once over the whole prompt, so that every GEMM feeds or reads it, and the other runs each operator alone on the whole array.
The hardware already provides the concurrency, and within a design's cut, the order in the artifact decides how much of it the work receives.
\end{abstract}
