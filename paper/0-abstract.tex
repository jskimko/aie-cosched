On client neural processing units (NPUs), a large language model (LLM) runs its operators on disjoint column groups of a spatial array, while one in-order command processor (CP) issues all of their work.
The CP's instruction order is therefore the array's schedule, and the toolchain fixes it in the instruction streams it emits.
In existing designs, this order makes column groups take turns on work that does not depend on each other, and neither packing operators into one command nor a second hardware context recovers the overlap.
We read the order from compiled streams, closed ones included, and identify each wait as a true dependence or a textbook false dependence on order or on storage.
An event model and a lower bound, built from timings of each operator run alone, then price candidate schedules before they run.
OPCORD reorders the CP's issue and renames the buffers of decode's loop into rings, under checkers that refuse any rewrite they cannot show legal, with kernels, driver, and firmware unchanged.
On an AMD XDNA~2 NPU, against the fastest existing schedule we measured for each design, OPCORD shortens the time to first token across five LLMs by $1.14$--$1.46\times$ from scratch and $1.19$--$1.51\times$ on appends to a cached context, decode by $1.16$--$1.27\times$ at a 16K-token context, and whole agent turns by $1.15$--$1.32\times$, with bit-identical outputs.
The hardware already provides the concurrency, and the instruction order rations it.
