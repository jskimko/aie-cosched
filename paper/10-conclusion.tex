\section{Conclusion}
\label{sec:conclusion}

On a spatial NPU whose work one in-order command processor issues, that processor's instruction order is the array's schedule, fixed in the compiled artifact.
Fused designs avoid reconfiguring the array between operators but can inherit an order in which independent groups take turns, and removing such a false order pays only under a condition, namely where the work it frees runs on core tiles and DMA channels that the work it waited on does not use, resources a rewrite cannot duplicate, with no true dependence between, in an amount set by how the design cuts its work and by the prompt length.
OPCORD therefore reads compiled designs, bounds each false order, prices the order and the column split per prompt length, and rewrites only what its checkers show legal.
Against the existing program on the shipped split that minimizes its time to first token, OPCORD shortens the time to first token by \E{X--Y}$\times$ on five LLMs at prompts of 1K to 32K tokens, and against the unmodified decode design its loop pass, which renames decode attention's buffers into rings, shortens decode by \E{X--Y}$\times$ at 16K-token contexts, with bit-identical outputs.
Across 112 designs on three stacks, every overlap gain we measure falls where the condition says one can arise, and a closed production stack leaves almost no overlap to recover in either of its prefill engines: one runs each layer's attention once over the whole prompt, so that every GEMM feeds or reads it, and the other runs each operator alone on the whole array.
What the composed order still pays is the price of overlap under the shared DRAM read cap and the command processor's and the host's work that the schedule does not hide, and the result suggests that toolchains should emit the order of issue as a priced choice per input size rather than as a fixed artifact.
