Concurrency on a spatial array is provided by the hardware and rationed by false dependences: at the one in-order command processor that issues every column group's work, and inside the loops of a single operator.
Both kinds are textbook order and name dependences, and both survive in designs that an expert has tuned, where the quantity a developer can compute on this device reads busy and where, in decode attention, removing only some of the waits on one cycle changes the time by less than 1\%.
Reading a design's order out of the instruction streams its stack has already emitted makes those waits addressable: each can be attributed to a class, priced from probes of each operator alone, and then removed by reordering issue or by renaming a loop's buffers, with the split of columns chosen for the regime.
What OPCORD recovers is the concurrency the expert designs leave unused, bit-identically and with the kernels, driver, and firmware unchanged, and what it leaves is the column groups' own busy time, which the bound shows is what now binds, together with the host work that runs between commands.
