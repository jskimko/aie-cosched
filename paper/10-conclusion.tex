\section{Conclusion}
\label{sec:conclusion}

% VALUE: one closing paragraph, standalone, as the chain: on a spatial NPU one in-order CP issues every group's work, so the compiled order is the schedule; fused designs avoid reconfiguration but inherit an operator-at-a-time order full of false dependences; removing one pays only where the freed work overlaps on non-duplicable resources with no true dependence, in an amount set by the cut and the prompt length; OPCORD reads, bounds, prices per length, and rewrites legally; the results and what the census shows; what remains, and what it implies for toolchains
% DECISION: no hardware wish list; the conclusion stands alone, with headline numbers only.
On a spatial NPU whose work one in-order command processor issues, that processor's instruction order is the array's schedule, fixed in the compiled artifact.
Fused designs avoid reconfiguring the array between operators but can inherit an order in which independent groups take turns.
Removing such a false dependence frees overlap beyond what buffers on a shared route let through only under a condition checkable from the artifacts, in an amount set by how the design cuts its work and by the prompt length.
OPCORD therefore reads compiled designs, bounds each false dependence, prices the order and the configuration per prompt length, and rewrites only what its checkers show legal.
Against the original program on the measured supported configuration that minimizes its TTFT, OPCORD shortens the time to first token by \PrefillGainLo--\PrefillGainHi$\times$ on five LLMs at prompts of 1K to 32K tokens.
Against the unmodified decode design, its loop pass, which renames decode attention's buffers into rings, shortens decode by \DecodeGainLo--\DecodeGainHi$\times$ at contexts of about 30K tokens, and both keep the outputs bit-identical.
Across the designs we read from three stacks, every overlap gain we measure falls where the condition says one can arise, and a closed production stack leaves little overlap to recover in either of its prefill engines.
What the composed order still pays is the price of overlap under the shared DRAM read cap and the command processor's and the host's work that the schedule does not hide.
Because the order stays the schedule however a design's kernels and cuts improve, the analysis and rewrites apply to each design a toolchain emits, and the result suggests that toolchains should emit the order of issue as a priced choice per input size rather than as a fixed artifact.
