\label{sec:conclusion}

On a spatial NPU whose work one in-order command processor issues, that processor's instruction order is the array's schedule, fixed in the compiled artifact, and a false order in it costs time only where deleting it lets work overlap on resources a rewrite cannot duplicate, with no true dependence between.
Because a design's cut into commands and the prompt length set how much work meets this condition, OPCORD prices orders and column splits per prompt length and removes only what its price clears and its checkers show legal.
Against the existing program on the shipped split that minimizes its time, the reorder across column groups shortens the time to first token by \E{X--Y}$\times$ on five LLMs, and renaming decode's buffers shortens each token by \E{X--Y}$\times$, with bit-identical outputs.
Across 112 designs on three stacks, the condition holds in one design family, and a closed production engine whose commands already keep their columns busy leaves almost nothing to remove.
What remains is the price of overlap under the shared DRAM read cap and the command processor's and the host's work that the schedule does not hide.
