Neural processing units (NPUs) such as the AMD XDNA~2 bring large language model (LLM) inference to client machines~\citep{rico2024xdna,linux-amdnpu}.
Such an NPU is now standard equipment, because a platform requirement of 40 trillion operations per second put one into mainstream laptops~\citep{copilotplus-reqs}.
% SOURCE: the Copilot+ PC hardware requirement of 40+ TOPS for the NPU (copilotplus-reqs).
It is a spatial dataflow array, on which a design runs each operator of an LLM as a flow on its own group of tiles, which today's designs lay out as whole columns and we call a column group, while one in-order command processor (CP) issues the work of every group, so the order of issues and waits in the compiled commands is the schedule that the array runs.
In the fused prefill that MLIR-AIR builds for each LLM~\citep{wang2026mlirair}, which runs the prompt in 128-token chunks and which with its host program we call the \emph{existing program}, attention's columns and the columns of the matrix multiplications (GEMMs) take turns, although attention on one chunk, which reads the QKV projections of that chunk and earlier ones, neither feeds nor reads the GEMMs of later chunks (Figure~\ref{fig:timeline}, top, for Llama-3.2-1B).
The measure a developer can compute, which divides the operators' summed time by the wall time, still reads the device as busy for 92--97\% of the time to first token (TTFT).
% SOURCE: busy 92-97% of TTFT at 512 / 2,048 / 4,096 tokens, each operator's isolated time less the dispatch floor, summed over the prefill (amd-npu e3acc8a prefill-e2/decomp.txt; Section 3.2).
Issued in another order, the same operators run together and reach the first token \E{X}$\times$ sooner on the same \emph{split}, which is the number of columns that attention takes, fixed by the design's build among a few values its build supports (Figure~\ref{fig:timeline}, bottom).
However, while compilers and mapping frameworks~\citep{hunhoff2025iron,symons2025stream} optimize what each operator computes and where it runs, how operators are composed and issued through the CP has received far less attention.

Developers trade between modular designs, which give each operator its own configuration and reconfigure the array between operators, and fused designs such as this one, which keep several operators resident in one configuration and avoid reconfiguring but inherit an order of issue that is fixed when the design and its host program are written.
Packing several operators into one command, as CUDA Graphs~\citep{nvidia-cudagraphs} and XRT's run lists~\citep{xrt-repo} do, amortizes launch cost but recovers none of the lost overlap, because a wait on one group delays every later issue, and a second hardware context shares the whole array in time~\citep{xdna-driver}.
% SOURCE: packing neutral and queued commands non-overlapping, 1.007-1.029 (vault lab-prefill-overlap (5)(b)); every hardware context is allocated all eight columns per the driver's source, and a one-column design on two contexts takes 1.97x one alone (Section 3).
GPUs met the same kind of wait when every stream shared one compute queue, and issuing work breadth first was the remedy until hardware queues removed it~\citep{rennich2012streams,nvidia-kepler-tuning}, whereas this NPU has one in-order CP per hardware context, so the order must be rewritten in the stream itself.
% SOURCE: FastFlowLM's flash prefill issues each command to one column group, 84-85% of W in single-group commands, one all-column command at 0.4-0.5% (aie-cosched aa4df07, passes/flm_command_cut.py, results/2026-10-25-flm-command-cut); in-command bound 1.000x with 82-87% exposure (terms4, rows 3c70af2; exposure a3ef131); the lowering preserves the program's order (mlir-air AIRRtToNpuPass.cpp; fused_prefill device.py preserve_shim_dma_order).

% VALUE: (3) the insight and the characterization: the CP's order is the array's schedule, fixed in the artifact, so every wait can be read from it; the waits are textbook false dependences and removing those on the critical path is the textbook remedy (cited); what this platform adds is when removal pays (overlap on resources a rewrite cannot duplicate, with no true dependence, including through the host) and that the design's cut and the prompt length set how much, so the order that pays changes with length and must be priced

The insight of this work is that, because the CP's instruction order is the array's schedule, fixed in the artifact a toolchain emits, every wait in a design, every column a wait holds idle, and which waits could free overlap can be read from that artifact.
The waits above are textbook order dependences, and decode attention's loop, which keeps one buffer per role so that each block's transfer waits on the previous block's compute, adds textbook name dependences~\citep{bernstein1966analysis,kuck1981dependence}, which together we call false orders (Section~\ref{subsec:losses}).
Removing those on the critical path is the textbook remedy~\citep{fields2003interaction}.
What this platform adds is when removing one frees overlap, namely only where two clauses hold: the work it frees runs on core tiles and DMA channels that the work it waited on does not use, resources a rewrite cannot duplicate, and no true dependence, on the device or through the host, lies between the two.
A buffer can be renamed into several slots, whereas a core tile or a DMA channel cannot.
Both clauses name resources and dependences that the artifacts and the host's accesses, read from its program or observed at the runtime's boundary, establish, so they can be decided before any duration is measured.

How a design cuts its work into configurations, commands, and buffers, and the length of the prompt, set how much work meets this condition.
The released designs of a closed production stack, FastFlowLM~\citep{fastflowlm-repo}, take two other shapes.
Its per-operator engine, which runs every LLM it ships apart from its flash designs, our five LLMs included, gives each operator its own configuration of nearly the whole array, so consecutive operators share their columns.
Its flash designs, which issue each command to one column group as the existing program does, run each layer's attention once over the whole prompt rather than in chunks, so every GEMM feeds or reads it and every turn between their groups is a true dependence.
The existing prefill instead runs over fixed-size chunks, and attention's work per chunk grows with the chunk's position in the prompt while the GEMMs' work stays fixed, so the balance between the two groups shifts with the prompt length, and with it whether the overlap repays the per-command costs of a new order.
The issue order that pays therefore changes with the prompt and must be priced per length rather than fixed, and the split that pays moves with the same balance, because more attention columns shorten attention but lengthen every GEMM.

In this work, we build OPCORD, which removes from compiled designs the false orders whose removal pays, choosing the prefill's order and split per prompt length with an event model.
This serves the common path rather than one stack, since designs generated by open compilers such as MLIR-AIR and IRON, on which researchers and industry build independently, inherit the order their toolchain emits, and OPCORD recovers what that order loses after compilation, while a team holding a closed stack's source can apply the same analysis and checkers to its own designs.
First, because the order sits in binaries whose source may be closed, its analysis reads a design's artifacts as a dependence graph over every agent that touches state, namely the CP with its transfers, the cores, and the host, accepts a reorder or a rename only where they and the host's accesses show it legal, and bounds what removing each false order can gain, replaying a closed design only to check a bound against measurement.
Second, because the artifact fixes the order of the work but not its durations, an event model, analytical in form with constants measured once by microbenchmarks, prices each candidate order and split per prompt length from timings of each operator run alone, and a short measurement settles near-ties when OPCORD plans a prompt length.
Third, a composer reorders issue across commands, a stream pass within one operator's stream, and a loop pass renames decode attention's buffers into rings, and because OPCORD rewrites designs it did not compile, each stands behind a checker that refuses any rewrite it cannot show legal, with kernels, driver, and firmware unchanged.
Against the existing program on the supported split that minimizes its TTFT, OPCORD shortens TTFT across five LLMs by \E{X--Y}$\times$ at prompts of 1K to 32K tokens, and its loop pass shortens decode by \E{X--Y}$\times$ at 16K-token contexts against the unmodified decode design, with bit-identical outputs.
Its choice of order and split stays within \E{X}\% of the measured minimum on every LLM and prompt length we measure, where every fixed rule we test loses up to \E{Y}\% somewhere.
Its analysis re-emits every stream we read from three stacks byte for byte, and its checkers refuse every illegal rewrite we inject.
Across the designs we read, every overlap gain we measure falls where the condition says one can arise, and FastFlowLM leaves almost no overlap to recover in either of its prefill engines, as the condition predicts, because every turn between its flash designs' groups is a true dependence and its per-operator engine runs each operator alone on the whole array.

In summary, the primary contributions of this work are as follows:
\begin{itemize}
    \item We identify that fused designs on a spatial NPU can serialize independent work through the order and buffers fixed when the design and its host program are written, and characterize when removing it pays: what rescheduling recovers is set by how a design cuts its work, from modular to fused and into commands and buffers, and by the prompt length, a characterization that predicts where gains arise and where they cannot.
    \item We develop an analysis that reads compiled NPU programs, closed ones included, as dependence graphs over every agent that touches state, accepts a reorder or a rename only where the artifact and the host's accesses show it legal, and bounds what each false order can recover.
    \item We design and implement OPCORD, a post-compilation rescheduler that, building on this analysis, rewrites issue order and buffers behind legality checkers and chooses the order and the column split per prompt length with an analytical event model, leaving kernels, driver, and firmware unchanged.
\end{itemize}
