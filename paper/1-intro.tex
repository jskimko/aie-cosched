\CLS{S}Spatial dataflow neural processing units (NPUs) in client devices, such as the AMD XDNA\texttrademark{}~2 architecture, are small for the large language models (LLMs) they run, so every design must decide how the model's operators share the array.
\CLS{S}On XDNA~2 (Figure~\ref{fig:timeline}a), the array's AI Engine tiles are arranged in columns, each with its own path to memory, and each operator runs as a dataflow on its own group of columns.
\CLS{D}A design either reconfigures the array between operators, which is simpler to program but costs time~\citep{vandelm2026configwall}, or holds several operators in one configuration as a \emph{fused} design, which avoids reconfiguration and lets operators on disjoint columns run at once, but makes them share the rest of the NPU.
\CLS{S}In particular, a fused design's work reaches the array through one in-order command processor (CP), in the order compiled into the design.
\CLS{S}The CP blocks at each wait, so it cannot issue work to idle columns until the awaited transfer completes, even when that work does not use the result (Figure~\ref{fig:timeline}b).
\CLS{S}For the MLIR-AIR (AIR) compiler~\citep{wang2026mlirair}, its fused prefill runs each layer over 128-token chunks and issues one operator per dispatch, so attention and the matrix multiplications (GEMMs) take turns on their columns even when there is no true dependence.

\CLS{D}Issuing the same operators on the same columns in a different order can reduce the time to first token (TTFT) of a Llama-3.2-1B implementation by \FigOneGain$\times$ at 4{,}096 tokens.

\CLS{SL}The insight of this work is that when an in-order command processor issues a spatial NPU's work, its issue order, fixed in the compiled program, is the array's schedule, so the waits that leave the array idle can be read, bounded, and removed from the compiled program itself.
\CLS{S}This follows from the dispatch architecture rather than from one device, so it holds where in-order issuers execute streams of asynchronous issues and blocking waits for engines that could otherwise run at once, as on early GPUs with a single work queue~\citep{rennich2012streams}.
\CLS{S}In AIR's designs, the waits that leave the array idle include \emph{false dependences} (Section~\ref{sec:background}), placed by the issue order in prefill and by buffers that every loop iteration reuses in decode.
\CLS{S}Removing one can save time where the waiting work needs neither the same engines nor the results of the work it waits on, which is an observable condition from the compiled program and the host's accesses prior to measurement (Section~\ref{subsec:question}).
\CLS{S}Therefore, how a design partitions its work decides where gains can arise.
\CLS{S}The prompt length then decides what they are worth.

\CLS{S}We present OPCORD (Section~\ref{sec:method}), which reads a design's compiled instruction streams as a dependence graph and bounds what removing each false dependence could recover before any rewrite.
\CLS{S}In open designs, it changes the issue order and renames buffers behind checkers that accept only rewrites they can show legal, and an event model chooses the order and the column groups for each prompt length.
\CLS{S}Because the analysis, the bound, and the legality conditions work on compiled instruction streams, they serve designs from open toolchains, such as AIR and IRON~\citep{hunhoff2025iron}, as well as closed ones, such as FastFlowLM (FLM;~\citealp{fastflowlm-repo}).

\CLS{X}This work makes three contributions:
\begin{itemize}
    \CLS{SL}\item We show that for an in-order command processor issuing a spatial NPU's work, the compiled issue order is the array's schedule, and that a design's partitioning decides where rescheduling can recover time, through a condition read from the compiled program, and the prompt length decides what it is worth.
    \CLS{SL}\item We develop an analyzer that reads compiled NPU programs, both open- and closed-source, as dependence graphs over the command processor, the engines, and the host, bounds what each false dependence can recover, and accepts only rewrites it shows legal.
    \CLS{SL}\item We design and implement OPCORD, a post-compilation rescheduler that rewrites issue order, dispatches, and buffers behind legality checkers and chooses the order and column groups for each prompt length with an analytical event model.
\end{itemize}
