\CLS{S}Neural processing units (NPUs) now ship in client devices~\citep{linux-amdnpu}, where they run large language models (LLMs) many times larger than their on-chip memory.
\CLS{S}On AMD's XDNA~2, for example, a spatial array of AI Engine tiles arranged in columns, each with its own path to memory, runs each operator as a dataflow on its own group of columns.
\CLS{E}Compilers such as MLIR-AIR (AIR)~\citep{wang2026mlirair} and IRON~\citep{hunhoff2025iron} decide what each operator computes and where it runs.
\CLS{D}A design either reconfigures the array between operators, which is simpler to program but costs time~\citep{vandelm2026configwall}, or holds several operators in one configuration as a \emph{fused} design, which avoids reconfiguration and lets operators on disjoint columns run at once, but makes them share the rest of the NPU.
\CLS{S}All of a fused design's work, in particular, reaches the array through one in-order command processor (CP), in the order compiled into the design.
\CLS{S}The CP blocks at each wait, so it cannot issue work to idle columns until the awaited transfer completes, even when that work does not use the result (Figure~\ref{fig:timeline}b).
\CLS{S}AIR's fused prefill runs each layer over 128-token chunks, and its order issues one operator per dispatch, stage by stage, so attention and the matrix multiplications (GEMMs) take turns on their columns, although attention on one chunk does not feed other chunks' GEMMs (Figure~\ref{fig:timeline}).

\CLS{D}Reissued on the same columns, the same operators reduce the time to first token (TTFT) of Llama-3.2-1B by \FigOneGain$\times$ at 4{,}096 tokens.

\CLS{S}Packing dispatches, as CUDA Graphs~\citep{nvidia-cudagraphs} and XRT's run lists~\citep{xrt-repo} do, amortizes launch cost but recovers none of the lost overlap, nor does a second hardware context, which shares the whole array in time~\citep{xdna-driver} (Section~\ref{subsec:semantics}).

\CLS{SL}The insight of this work is that, on a spatial NPU whose work one in-order command processor issues, that processor's instruction order is the array's schedule, fixed in the compiled artifact.
\CLS{SL}So the waits that leave the array idle can be read, bounded, and removed from the artifact itself, after compilation.
\CLS{S}The structure that OPCORD exploits is a property of the dispatch architecture rather than of one device, since it holds wherever one issuer executes a compiled stream of asynchronous issues and blocking waits on behalf of engines that could otherwise run at once, as the single work queue of early GPUs did before per-stream hardware queues~\citep{rennich2012streams}.
\CLS{S}These waits are false dependences (Section~\ref{sec:background}), which the issue order places in AIR's prefill and single buffers place in its decode.
\CLS{S}Whether removing one frees time depends on which resources the freed and the awaited work share and on whether one still consumes the other's results through other work or a host step (Section~\ref{subsec:question}).
\CLS{S}This condition is read from the artifacts and the host's accesses before any duration is measured, so how a design partitions its work decides where gains can arise, and the prompt length, through the durations it sets, what they are worth.

% DECISION: FastFlowLM is described by what it ships, as its current release; no claim about how its order was chosen.
\CLS{S}Built on this insight, OPCORD (Section~\ref{sec:method}) reads a design's compiled instruction streams, including closed binaries such as the engines of the current release of FastFlowLM (FLM)~\citep{fastflowlm-repo}, as a graph of dependences among all agents that touch state, and bounds what removing each false dependence could recover before any rewrite is built.
\CLS{S}In open designs, it reorders issue so that every column group's work is issued before the CP waits on any, and renames buffers, each rewrite behind a checker that accepts only rewrites the artifact and the host's accesses show legal.
\CLS{S}Because the order that pays and the configuration that minimizes TTFT, namely the column split between attention and the GEMMs, both change with the prompt, an event model prices each candidate per prompt length.
\CLS{S}Since the analysis, the bound, and the legality conditions work on any stack's instruction streams, OPCORD serves designs from open compilers such as AIR and IRON, on which researchers and industry build independently, and a team with a closed stack's source can run the same analysis and checkers on its own designs.

\CLS{X}This work makes three contributions:
\begin{itemize}
    \CLS{SL}\item We show that on a spatial NPU whose work one in-order command processor issues, the compiled order is the array's schedule, and that how much rescheduling recovers is set by how a design partitions its work and by the prompt length, as predicted by a condition checkable from the artifacts.
    \CLS{SL}\item We develop an analysis that reads compiled NPU programs, closed ones included, as dependence graphs over every agent that touches state, bounds what each false dependence can recover, and accepts only rewrites it shows legal.
    \CLS{SL}\item We design and implement OPCORD, a post-compilation rescheduler that rewrites issue order and buffers behind legality checkers and chooses the order and configuration per prompt length with an analytical event model.
\end{itemize}
