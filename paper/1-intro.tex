Neural processing units (NPUs) such as the AMD XDNA~2 bring large language model (LLM) inference to client machines~\citep{rico2024xdna,linux-amdnpu}.
Such an NPU is now standard equipment, because a platform requirement of 40 trillion operations per second put one into mainstream laptops~\citep{copilotplus-reqs}.
% SOURCE: the Copilot+ PC hardware requirement of 40+ TOPS for the NPU (copilotplus-reqs).
It runs each operator of an LLM on a group of columns of a spatial array, and one in-order command processor (CP) issues the work of every group.
In the prefill that MLIR-AIR builds for Llama-3.2-1B~\citep{wang2026mlirair}, which we call the \emph{existing program}, attention's columns and the columns of the matrix multiplications (GEMMs) take turns, although neither consumes the other's current work (Figure~\ref{fig:timeline}, top).
The measure a developer can compute, which divides the operators' summed time by the wall time, still reads the device as busy for 92--97\% of the time to first token (TTFT).
% SOURCE: busy 92-97% of TTFT at 512 / 2,048 / 4,096 tokens, each operator's isolated time less the dispatch floor, summed over the prefill (amd-npu e3acc8a prefill-e2/decomp.txt; Section 3.3).
Issued in another order, the same operators run together and reach the first token \E{X}$\times$ sooner on the same split (Figure~\ref{fig:timeline}, bottom).
However, while compilers and mapping frameworks~\citep{hunhoff2025iron,symons2025stream} optimize what each operator computes and where it runs, how operators are composed and issued through the CP has received far less attention.

None of the fixes a developer would reach for first recovers this overlap.
Packing several operators into one command, as CUDA Graphs~\citep{nvidia-cudagraphs} and XRT's run lists~\citep{xrt-repo} do, amortizes launch cost but creates no overlap, because a synchronization on one column group delays every later issue, and a second hardware context shares the whole array in time~\citep{xdna-driver}.
% SOURCE: packing neutral and queued commands non-overlapping, 1.007-1.029 (vault lab-prefill-overlap (5)(b)); every hardware context is allocated all eight columns per the driver's source, and a one-column design on two contexts takes 1.97x one alone (Section 3).
Nor can a compiler choose a better order, because the host composes the commands at run time, where no compile for this NPU sees their order, and choosing among orders needs the durations of the work, which no compile has.

% DECISION: false dependences, their classes, reordering and renaming are textbook and cited; the finding is the condition on this platform and its dependence on the cut and the shape, never "false dependences cost time".
The insight of this work is that the CP's instruction order is the array's schedule, fixed in the artifact a toolchain emits, so every wait in a design, and every column a wait holds idle, can be read from that artifact.
The waits above are textbook order and name dependences~\citep{bernstein1966analysis,kuck1981dependence}, and removing those on the critical path is the textbook remedy~\citep{fields2003interaction}.
What this platform adds is the condition under which one costs time, namely that deleting it lets work overlap on resources a rewrite cannot duplicate, with no true dependence on the device or through the host between.
How a design cuts its work into commands, and the length of the prompt, set how much work meets this condition, so the order that pays changes with the prompt and must be priced rather than fixed.
MLIR-AIR's chunked prefill meets the condition, whereas a closed production engine that we read, FastFlowLM~\citep{fastflowlm-repo}, issues commands that already keep their columns busy, which leaves almost nothing to remove.
% SOURCE: FastFlowLM's in-command bound 1.000x with 82-87% exposure (terms4, rows 3c70af2; exposure a3ef131).

% VALUE: (4) this work: OPCORD, which removes the false orders its price clears (its parts are the contribution items below); headline results against the existing program on its best shipped split, and the event model's choice quality
In this work, we build OPCORD, which removes the false orders of compiled designs that its price clears.
Against the existing program on the shipped split that minimizes its TTFT, OPCORD shortens TTFT across five LLMs by \E{X--Y}$\times$ at prompts up to 32K tokens and decode by \E{X--Y}$\times$, with bit-identical outputs.
Its choice of order and split stays within \E{X}\% of the measured minimum on every configuration, where every fixed rule we test loses up to \E{Y}\% somewhere.

In summary, the primary contributions of this work are as follows:
\begin{itemize}
    \item A method for analysing compiled NPU programs, closed ones included, as dependence graphs over every agent that touches state, which decides from the artifacts alone whether a reorder or a rename is legal.
    \item A condition for when a false order costs time on a spatial NPU, tested on a census of 112 designs from three stacks and by varying a synthetic design.
    \item An event model and bound, analytical in form with constants from microbenchmarks, that price an order and a split per prompt length before they run.
    \item The design and implementation of OPCORD, a composer and two MLIR-AIE passes that remove the false orders their price clears from compiled designs behind legality checkers, with the kernels, driver, and firmware unchanged.
\end{itemize}
